# ADR-0045: 面板窗口唤出前修复显示状态

状态：已接受　日期：2026-11-10　关联：ADR-0016、ADR-0027、ADR-0023

## 背景

快速面板与速览面板窗口在 `tauri.conf.json` 里声明为启动即创建且隐藏（`visible: false`），物理尺寸由 Tauri 按「创建那一刻」的屏幕缩放比从逻辑尺寸（380×320 / 320×420）换算定死。实测暴露两类故障，均在「程序运行中显示器设置变化、随后唤出」时出现，重启即恢复：

1. **内容裁切**：Windows 不给隐藏窗口投递 `WM_DPICHANGED`，缩放比变化后窗口缓存 scale 与 WebView2 内容视口一起停在旧值；唤出时内容按旧缩放排版，被新物理尺寸的窗口裁掉（右侧截断）。
2. **位置越界**：分辨率改小或显示器被拔后，窗口坐标按旧屏幕算的，右半截落在屏幕外，甚至整只唤不出来。

两者都是运行时状态过期，无任何持久化损坏。

## 决策

**在每次唤出前（`show()` 之前）幂等修复窗口矩形，而不是监听显示变化实时维护。**

- 时机选唤出：显示变化对隐藏窗口没有可靠事件可听（`WM_DISPLAYCHANGE`/`WM_DPICHANGED` 均不投递隐藏窗口），而唤出是唯一确定需要窗口处于正确状态的时机。修复函数 `panel_window::ensure_on_screen` 是普通函数，热键（`toggle_quick`）、托盘菜单、前端命令（`toggle_quick_window`）、速览锚定（`toggle_glance`）四处共用。
- 尺寸：物理尺寸按「当前逻辑尺寸 × 目标显示器 scale」重算。当前逻辑尺寸 = 当前物理尺寸 ÷ 窗口缓存 scale——该比值恒成立（每次物理尺寸落笔都用的当时缓存值，隐藏期二者一起过期）。换算必须用**目标显示器的** scale，不能信窗口缓存值（ADR-0027 同款教训）。
- 位置：目标显示器取与窗口当前矩形相交面积最大者（保留用户拖动位置，越界才钳回工作区）；全不相交（显示器被拔）退光标所在显示器，再退第一个显示器。
- 收尾：`ScaleFactorChanged` 事件到达时（tao 已套用 Windows 建议矩形并更新缓存 scale）对面板窗口再修一次——既纠正「唤出前已预修正的尺寸被建议矩形按旧比值二次换算打歪」，也以一次真实 WM_SIZE 逼 WebView2 按新 DPI 重排；覆盖可见状态跨屏拖动的场景。主窗口不在此列：用户可调尺寸、居中创建，Windows 对可见窗口的分辨率变化有默认调整，故障面窄。

## 后果

- 未变化时（绝大多数唤出）零窗口调用：尺寸换算与位置钳制都是恒等时跳过，不引入抖动。
- 高度自适应（`useFitWindowHeight`）不受影响：它只在 show 后补高度，宽度与位置由本修复负责；唤出后读到的窗口 scale 已是修复后的新值。
- 前端零改动。三条唤出路径 + ScaleFactorChanged 收尾共一处封装，测试以纯函数锁定（相交面积/目标选择/跨 scale 换算/钳回）。
- 被拔显示器上唤出会落到光标所在屏（用户正在用的屏）而非消失；拖动习惯在未越界时完全保留。
