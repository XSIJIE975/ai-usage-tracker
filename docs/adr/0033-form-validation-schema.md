# 表单校验层：schema 只出错误码，文案在渲染时翻

Status: accepted

## Context

供应商配置弹窗此前不校验必填：新建一份配置、五格全空也能直接保存，保存后卡片长期停在 `needs_config`，用户看不出少了哪一格。要补校验，三个既有约束先决定了方案的形状：

- **错误文案必须跟着界面语言走。** 本项目的中文源文案本身就是 i18n 键（`src/i18n/translate.ts`），词典只有一份。resolver 的默认行为是把成品 message 冻进 form state——那样切语言时已经显示的错误会卡在旧语言。
- **格式判定已有事实源。** `isValidSessionCookieValue`（`src/providers/qoder.ts`）与 `isValidCookiePartValue` / `isValidUserAgentValue`（`src/providers/workbuddy.ts`）与 Rust 发请求时的校验同口径，且被 `diagnostics.ts` 的连通性探测复用。ADR 里定下的「测得过即存得过」要靠这层成立。
- **字段按种类动态。** 5 种供应商各 1–3 格凭据，加阈值、站点、备注；`KIND_CONFIGS` 早就是这个形态的声明表。

## Decision

**表单状态与校验时机交给 react-hook-form 7，规则用 zod 4 声明，错误以码的形式在两层之间流动。**

- **一张字段规格表同时驱动渲染与校验**：`src/forms/form-specs.ts` 里每个凭据格带 `required` 与 `validate`，`validate` 只做「引用供应商模块已有谓词 → 返回错误码」，不重抄正则。schema 由这张表装配（`src/forms/instance-schema.ts`），接第 6 家供应商仍然只加一条 spec。
- **schema 只产出错误码**，码 → 中文源文案在 `src/forms/error-codes.ts`，渲染时才过一次 `t()`。需要实参的文案（阈值范围）由渲染端从字段规格取，不从 form state 穿参——resolver 的 `FieldError` 里没有 params 的位置。
- **表单值就是事实源，必填不分新建/编辑**：编辑态会把库里的凭据明文回填进格子，所以格子空了是一次**主动删除**，不是「没填」——必填格清空即报缺失并挡住保存，选填格清空即按 `null` 写回（真删）。保存只提交与已存值的差集，没动过的格子不重写。
  唯一例外是凭据还没从库里读出来（未解锁 / 读取失败 / 尚未返回）：那时空格子代表「没读到」，既不按必填拦（否则锁库时连备注都改不动），保存路径也整段跳过凭据写入（否则会把没加载到的格子写成 `null`，等于删库）。
- **「清除」按钮只清输入框**：写库只发生在保存，取消就什么都没改。代价是它不再是「删掉一项必填凭据」的入口——必填格空着保存会被拦下，要彻底去掉一份配置走删除实例。徽标继续只说「库里有没有」这一件事：空框 + 必填错误已经把状态讲完了，再加一个「待清除」既重复、又对必填格许愿（保存根本不会通过）。
- **校验时机 `mode: "onTouched"`**：首次失焦后跟随输入，既不在用户还没写完就报，也不等到提交才一次糊满屏。
- **无障碍原语收敛到 `src/components/ui/field.tsx`**：`data-invalid` / `aria-invalid` / `aria-describedby`，`FieldError` 带 `role="alert"` 且只在错误出现那一刻挂载。
- **提交失败按视觉顺序聚焦首个错误字段**（`shouldFocusError: false`）：RHF 自己那套按已注册 ref 的顺序找，凭据格走 Controller 没有 ref，焦点会被丢给备注框。
- **阈值不再静默 clamp**：原先超范围会被 `Math.min/Math.max` 改成用户没写过的数，现在报范围错误。备注补 60 字上限（此前两侧都不管）。
- **`form-specs.ts` 留在 `src/forms/`，不放 `src/providers/`**：`allowed-hosts.test.ts` 按目录扫「前端会打出去的地址」，而这张表里的域名是给人看的取数指引，混进去会让那道守卫失去「文件即会发请求」的语义。

Rust 侧的字符级校验保留不动，作为第二道闸（纵深，不是主界面）。

## Considered Options

- **自写 ~60 行 hook + valibot**（增量体积 2–7 kB vs RHF 25 kB）：体积这条在 Tauri 桌面端本就不成立（本地加载）；而"所有供应商字段都要接、长期维护"意味着必填矩阵、聚焦定位、touched 追踪、将来可能的数组字段都自己背。测试覆盖的是自己写的轮子。
- **TanStack Form**：headless 契合度最高，但周下载量级与 API 稳定度都逊于 RHF，收益不足以换掉生态。
- **只用 HTML 原生 `required` / `min` / `max`**：零依赖，但错误气泡是浏览器文案（不吃 i18n），且 Radix 的 Switch/自绘 Select 根本不走原生校验。
- **把格式规则抄进 zod**：省一层引用，代价是分裂成两份事实——前端放行、Rust 拒绝，最后退化成"存进去等 401"，正是这次要修的症状。

## Consequences

- 必填集与各 provider `needs_config` 判据的一致性有测试钉住（`instance-schema.test.ts` 的 `REQUIRED_SLOTS` 与 spec 对拉）；改判据不改表会让那条用例变红。同文件另有一条守卫 schema 只会产出词典里登记过的码。
- Formik 未纳入考虑：2.4.9 之后长期无发布，事实停维。
- 一处 jsdom 边界值得记：Radix 的焦点陷阱靠 `composedPath` 判断焦点是否越界，jsdom 支持不全，会把测试刚设好的焦点又抢回首元素。所以组件测试断言的是「我们发起了对某字段的聚焦」，不是「焦点停在那儿」——后者在真实浏览器成立，在 jsdom 测的是环境缺陷。
- 两条走过的弯路记在这里，免得再走。其一：初版把「编辑态留空」当成「不改动已存凭据」（那是凭据框只放占位符、配没配看徽标时代的语义），于是用户把回填好的值整格删掉、点保存，既不报错也不写库，弹窗还按成功关掉，重开一看旧值又回来了——操作被静默吞掉。判据要看清控件里当下显示的是什么：**格子有回填值时，空值就是一次编辑**。其二：为了保住「必填凭据也能删掉」这条出路，让「清除」按钮绕过表单直接写库，结果同一个弹窗里出现两套持久化时机——点 X 立刻生效、改别的要等保存，于是「清了没保存」会留下用户没预期的状态。收敛成一条不变量：**这个弹窗里除了保存，没有第二条写库路径**。
