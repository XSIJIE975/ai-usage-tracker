# 开机自启与静默启动：静默仅作用于自启路径

Status: accepted

## Context

新需求两个设置：开机自启（随系统启动运行程序）与静默启动（启动不显示主窗口，仅托盘驻留），后者按需求仅在前者开启时展示。静默启动的文案「程序启动时不显示主窗口」可读成全局语义（一切启动都静默），与 UI 从属位置暗示的「仅自启生效」冲突，必须钉死一个。

全局语义（每次启动读设置决定可见性）有三处硬伤：关闭自启后选项在 UI 上隐藏但设置仍在暗中生效，门控与语义自相矛盾；手动双击图标「看似没反应」；更新安装后 relaunch 同样静默，用户在设置页点完安装窗口消失，易误判失败。

## Decision

- 静默启动是开机自启的属性而非程序的启动行为：以自启项携带 `--silent` 启动参数实现，只有自启的那次启动隐藏主窗口。手动启动、更新后 relaunch、唤起已运行实例（单实例回调）一律显示主窗口——relaunch 不带参数，天然无需区分「更新重启」。
- 关闭自启时静默启动复位为关。区别于「供应商自动刷新」受总开关门控时保留值的先例：此处语义从属，选项隐藏后残留旧值没有意义。存储不变式 `silentStart ⇒ autoStart` 由前端在关闭自启时同写两键维持。
- 主窗口改为 `visible: false`，启动时解析命令行：无 `--silent` 则 show。避免「先显示再隐藏」的闪烁；静默启动下 webview 照常加载（托盘、自动刷新、通知依赖它），与现有「关窗驻留」状态同构。
- 不用官方 tauri-plugin-autostart 插件：其启动参数在 init 时固定，无法随静默启动开关动态重写自启项。改用其底层的 auto-launch crate 在 Rust 命令中直调，切换静默启动时以不同参数重建自启项；程序启动时若设置开启则重新 enable 一次（幂等），顺带修正安装路径变化，且不影响任务管理器的系统级禁用（StartupApproved 是另一处键值）。

## Consequences

- NSIS 卸载器需清理 Run 键残留（加 uninstaller hook）；macOS LaunchAgent / Linux XDG 自启文件残留无害，暂不处理。
- 自启注册（写注册表/plist/desktop 文件）先于设置持久化执行：注册失败则不保存设置并提示错误，避免 UI 状态与系统状态脱节。
- 开发模式下注册的是 debug 可执行文件路径，仅影响本机开发环境。
