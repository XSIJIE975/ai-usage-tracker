# 凭据库改用设备密钥，废除主密码

Status: accepted, supersedes ADR-0004

每次启动输入主密码被证实是不必要的摩擦。经讨论，用户接受以缩小安全边界换取零输入体验：凭据库废除主密码，改为随机生成 256 位设备密钥并托管于操作系统钥匙串（Windows Credential Manager / macOS Keychain / Linux Secret Service，经 keyring crate），凭据文件沿用现有 AES-256-GCM 加密层。安全目标明确收缩为"凭据文件被复制到其他机器后无法离线解密"。

## Considered Options

- 保留主密码（ADR-0004 现状）：每次启动输密码，本次变更的直接动机就是去掉它。
- 硬件指纹派生密钥（主板 UUID、卷序列号等 + KDF）：指纹在本机可被其他程序读取、接近半明文，且更换硬件即失效；随机设备密钥强度更高。这正是 ADR-0004 当年否决机器绑定时指的"安全性较弱"，故仍不采用。
- 仅 Windows DPAPI：最简单，但发布流程同时打包 macOS（dmg）与 Linux（deb/appimage），不能放弃跨平台。

## Consequences

- 能登录本机系统账户的人或进程可通过程序直接获得明文凭据，无需任何解密——这是明确接受的取舍，不是疏漏。
- 换机、重装系统、重置账户密码或 Linux 无 Secret Service 时钥匙串失效：凭据不可恢复，降级为引导重新录入（所有凭据均可从服务商网页找回）。刻意不提供导出/导入，避免明文落盘缺口。
- 旧格式凭据库（argon2id + 主密码）的迁移路径需长期保留：升级后首次启动引导一次性凭据库迁移（最后输一次旧密码），跳过后可在设置页补做；因此 `argon2` 依赖不可移除。
- SQLite 数据库继续明文存储：其中不含凭据，不在本决策范围内。
