# ADR-0040: 主窗口不设顶层页签——设置下沉为右侧抽屉

状态：已接受　日期：2026-10-08　关联：ADR-0011、ADR-0014

## 背景

「总览/设置」两档分段器从初始提交起就在主窗口顶栏，设置视图另占一份 `max-w-3xl` 居中版心。这个形态在本仓库已经被削过两次：ADR-0011 把设置页里与 DeepSeek 并列的供应商页签整块撤掉，实例凭据与阈值改由卡片配置弹窗承载；统计也从顶层页签下沉为卡片触发的右侧抽屉（`docs/DESIGN.md` §6.6）。剩下的设置内容如今全是全局开关与外观/托盘/速览形态，并且逐项即时写入——它是一个没有提交动作的长内容列表，却与主视图平权占着一个页签位，看数据和改配置必须来回切。

分段器本身还带一条隐性契约：新增顶层页签只是「options 里加一项」的廉价操作，页签越多，主视图越退化成容器壳。

## 决策

1. **主窗口不再承载顶层页签**：`ViewKey`、`view` 状态、顶栏 `Segmented`、`max-w-3xl` 版心一并撤销，`<main>` 只装总览（卡片网格 + 共享错误横幅）。这是规则而不是一次性清理——今后新增的功能面不得回来占顶栏页签位。

2. **设置改为顶栏最右的齿轮 `IconButton` 打开右侧抽屉**（`views/settings/SettingsSheet.tsx`，宽 `min(40rem,100vw)`，`SheetHeader` + `SheetBody` 全高滚动），内容原样平移（迁移卡 → 密钥丢失横幅 → 十个区块，顺序不变）。开关状态只在本会话持有、不持久化，与原先页签的 `useState` 同口径。

3. **弹层选型按容量，不按读写**：一屏放得下、有显式提交动作的表单走居中 `Dialog`（实例配置、重置卡）；需要滚动的长内容走右侧 `Sheet`（统计、成长中心、设置）。§6.9 原「`Dialog` = 表单类 / `Sheet` = 详情类」的二分不再成立——设置既可写又长，正好落在两头之间；容量作主轴后，写入时机降为第二轴（`Dialog` 有取消/保存，`Sheet` 里的设置靠 write-through，没有提交概念，因此设置抽屉不设页脚）。

4. **宽度取 640px 而非 768px**：主窗口 `minWidth: 720`（`tauri.conf.json`）是会被真实用到的档位，768px 抽屉在最小窗口下等于铺满，抽屉形态名存实亡。640px 下「托盘图标」三列预览每列约 179px、卡内净宽约 155px，标题四字与百分比 caption 仍单行放得下。

## 后果

- 入口从带文字的分段器降为纯图标，「设置」的发现性依赖齿轮这个通用符号。各处「请在设置中…」的文案（`useAppStore` 的凭据提示、Rust 侧快捷键冲突提示、各家 `needs_config`）保持纯文本：凭据类问题的真实修法是卡片 ⋯ → 编辑配置，把文案做成可点会给同一动作画两套入口。
- 顶栏「新版本 vX」徽标原本 `setView("settings")`，现在改为开抽屉并把滚动区定位到「检查更新」卡片（`Card id="settings-update-card"` 作锚点）。抽屉关闭即卸载，所以每次打开默认回到顶部，只有这条链路带定位意图。
- 快速面板快捷键录制期间 ESC 关不掉抽屉（录制器用 capture + `stopPropagation`）——录制中本就不该被 ESC 撤走，因此不改录制器。
- 待迁移状态不在顶栏另加提示点：全屏 `MigrationScreen` 每次启动都已挡在前面，同一状态不该由两个控件各说一遍（「一个状态只让一个控件说」）。
- `views/SettingsView.tsx` 删除、内容并入 `SettingsSheet`：「View」这个命名是顶层页签时代的产物，页签没了不该留下。
