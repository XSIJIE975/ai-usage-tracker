# 速览面板四方位锚定与高度变化贴栏

Status: accepted

## Context

ADR-0016 的锚定只区分「顶部菜单栏 → 面板放下方，其余 → 放上方」，且高度自适应的 `keepBottom` 写死**底边**锚定。Windows 底部任务栏下两者恰好一致所以正常；macOS 顶部菜单栏下面板首开是**顶边**贴栏、高度补间却平移顶边去保底边——切换列表/卡片形态即漂离菜单栏（用户反馈，Windows 顶部任务栏同病）。Linux 各 DE 支持左/右面板，首开位置也会摆错。同路径还有两处潜伏问题：托盘图标矩形的 DPI 换算用的是**主窗口** scale（托盘在主屏、主窗口驻留异 DPI 副屏时会偏）；ADR-0016 措辞「右对齐」与实现（居中+钳制）漂移。

## Decision

- **四方位统一规则**：贴系统栏的那条边不动，面板朝屏幕中心伸缩，沿栏方向以图标中心对齐并钳制在工作区内。状态栏方位按图标矩形相对**显示器完整 bounds** 的最近边缘带判定，与操作系统无关——Windows 顶部任务栏与 macOS 菜单栏同走 Top 分支，OS 仅在图标坐标不可靠时参与兜底（macOS 假设顶、其余假设底）。用完整 bounds 而非工作区：X11 下多数 DE 的工作区本就不可靠（ADR-0016 的教训）。
- **贴栏边来源 = 前端嗅探**：高度变化时由 hook 拿窗口当前位置对比所在显示器工作区边缘——贴顶边则顶边不动（从此不再逐帧 setPosition，顺带消抖），贴底边则维持底边锚定补间，都不贴（左右栏 / Win11 flyout 回退后被移动 / 坐标不可靠）则纯改尺寸、坐标不动。不新增 Rust→前端的状态传递。
- **多 DPI**：托盘图标矩形换算改用「光标所在显示器」的 scale，兜底主窗口 scale → 1.0。
- **对齐口径**：统一为居中+钳制（代码现状），修正 ADR-0016 措辞。

## Considered Options（贴栏边来源）

- Rust show 时算好方位随事件下发：单一事实源，但要新增 IPC 契约并维护窗口状态同步——否决。
- 按操作系统写死（macOS 顶、其余底）：覆盖不了 Windows 顶部任务栏与 Linux 四边——否决。
- 前端嗅探（选定）：零契约；Win11 溢出区 flyout 回退右下角自然落入贴底分支；异常场景退化为纯改尺寸，安全。

## Consequences

- 锚定核心拆为无窗口依赖的纯函数（Rust `compute_anchor`/`detect_bar_side`、前端 `snappedEdge`）并补单测：4 方位 × 钳制 × 多显示器负坐标 × 兜底——本机只有 Windows，这是唯一能自动验证全端行为的手段。
- 快速面板不启用嗅探（可拖动、左上角固定），行为零变化。
- 诊断日志本次不加：几何日志（显示器 bounds / 图标矩形 / 判定方位 / 前后坐标）并入后续统一日志模块（收集/上报）一并规划。
