# 错误快照落库与隐藏面板零抓取

Status: accepted

补上 ADR-0019 快照收敛的两处语义缝隙：失败快照不落库（错误态只在发起方内存里，跨窗口不一致），以及隐藏面板照常发起全量网络抓取（与「不可见 webview 不吃数据」的收敛门控不对称）。

## Context

2026-09-11 代码核对：

- `save_snapshot` 只在 fetch 成功分支执行；刷新失败的 error 快照（`fallbackSnapshot`）只存在于发起方内存。事件照发、其余窗口 `reloadSnapshots` 读回的是**旧成功快照**——同一实例在不同窗口一个显示错误、一个显示旧数据，告警的解除也只在发起方生效。
- 反向问题：一旦错误态进入事实源，`evaluateRules` 的既有契约「快照非 ok → 视为正常（用于解除告警态）」会把已激活的告警**解除**；网络恢复后第一次成功刷新又看到越阈边沿，再发一次通知——错误处理本身制造重复通知。
- 面板窗口的 `vault-status-changed` / `credentials-changed` / `instances-changed` 监听都走 `syncFromBackend()`，内含无条件 `refreshAll()`（全部实例 HTTP 抓取）且无可见性守卫：主窗口增删一个实例，隐藏中的 quick/glance 会对全部供应商发起完整抓取，再各自广播 `refresh-completed` 反向触发主窗口重读。ADR-0019 的可见性门控只挡了 `reloadSnapshots`，没挡抓取。
- 供应商自动刷新（默认 5 分钟一轮）无 in-flight 去重：慢的旧一轮 fetch 可在新一轮读回之后才落库，用旧数据覆盖 DB 与 UI（用量回退）。

## Decision

**刷新失败也落库成为事实源的一部分；告警对错误态「冻结而非解除」；面板隐藏时跳过全量网络抓取、主窗口豁免。**

1. **错误快照落库**：`status=error`、无用量行，随「先落库、后广播」的既有流程收敛到所有窗口。托盘与卡片诚实显示错误，而不是无限期的旧数据——「没有数据」与「有旧数据」是两种事实。供应商宕机期间用量环因无可绘数据回退默认图标，这是诚实语义的代价。
2. **告警冻结语义**：错误快照对告警是**未知**而非正常——既不触发新告警、也不解除已激活告警。`evaluateRules` 的「快照非 ok 视为正常」契约相应收窄为「非 ok 冻结」；协调器跳过该实例本轮的边沿求值。网络恢复后边沿状态未被重置，不会重复通知。
3. **零抓取的门控范围**：面板（quick / glance）隐藏时，`instances-changed` 等事件只做本地轻量重读（`reloadInstances` / `loadInitial`——IPC 便宜，保证唤起时结构正确），跳过 `refreshAll`；唤起事件照旧走收敛（先重读再按需刷新）。**主窗口豁免**：主窗口隐藏即驻留托盘，它的自动刷新是数据心跳，停掉它常驻模式下托盘数字就停摆——可见性门控只约束面板。自动刷新定时器在隐藏面板中同样静默。
4. **in-flight 去重**：`refreshAll` 进行中时再次调用直接复用进行中的那一轮（手动触发可打断计时但不重入），堵住 StrictMode 双挂载与「面板唤起撞上定时器」的重复抓取。

## Considered Options

- **错误态不落库、随 `refresh-completed` 载荷携带**：改动小，但每个消费方都要写合并逻辑，且 `reloadSnapshots` 读库时错误态消失、回退旧数据——「事实源不含失败」的认知缺口仍在。
- **错误快照单独存表、展示层合并**：两套事实源，读取路径翻倍，过度设计。
- **面板隐藏时连本地重读也跳过**：唤起路径变重（结构+快照都要补，首帧闪变），且实例结构过期的时间窗更长；本地 IPC 的成本可忽略。

## Consequences

- 快照历史的采样序列含错误点（`status` 字段区分），未来做历史视图时宕机时段可见——比「稀疏但只含成功」更接近真相。
- `get_latest_snapshots` 语义不变（每实例最新一行），但行可能是错误快照：所有快照消费方（托盘候选、快速面板、卡片）对 `status=error` 走「无数据/错误」分支，多数既有代码已按 `status!=="ok"` 防御，改动集中在落库路径与告警契约。
- CONTEXT.md「快照事实源」词条更新为含错误采样，新增「错误快照」词条；ADR-0022 的冻结语义与告警唯一评估在同一批实现。
- 抓取频率显著下降（隐藏面板不再开闸），但「三窗口均可发起抓取」的结构未变——ADR-0019 预留的「单一抓取者」演进方向保持开放。
