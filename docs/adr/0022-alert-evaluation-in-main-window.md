# 告警评估收敛主窗口与文案模板化

Status: accepted

修正告警子系统的两处结构性缺陷：评估权按窗口复制导致跨窗口重复通知，文案硬编码中文绕过 i18n 管道导致英文用户收到中文告警。前者收敛为「主窗口唯一评估」，后者统一到项目既有的「模板 + params」机制。

## Context

2026-09-11 代码核对：

- `AlertCoordinator` 是模块级单例（`src/store/useAlertStore.ts:44`），但 webview 相互隔离——main / quick / glance 三扇窗口各持一份。三扇窗口都通过 `refreshAll → observe` 参与告警评估（`Dashboard.tsx` / `QuickWindow.tsx` / `GlanceWindow.tsx` 挂载与自动刷新路径）。
- `alert-state-changed` 广播只同步 `active` 布尔表（托盘图标与横幅用），**不同步边沿触发与冷却状态**。同一实例越阈值时，主窗口与任一面板的协调器各自看到一次「正常 → 越阈」边沿，各自触发 `notify`：系统通知弹两次、通知中心落两条记录（`add_notification` 写的是同一个库），两边各自 6 小时冷却、互不知晓。
- 告警文案（`evaluate.ts` 产出的 fire `title`/`body`，如「智谱 GLM 额度耗尽」「已用尽（100%），等待重置恢复。」）拼好后**原样**传给 `sendNotification` 与 `add_notification`，全程不经 `t()`。英文用户的系统通知与通知中心均为中文；`en.ts` 里「DeepSeek 余额告警」等键是死键（无翻译出口），且「智谱配额告警」与实际拼出的「智谱 GLM 配额告警」（`alertTitle` 的备注/供应商名分支）对不上，「请及时充值。」只是 body 整句的片段、永远匹配不到。
- 快照收敛（ADR-0019）后，主窗口收到别窗 `refresh-completed` 会重读快照，但 `reloadSnapshots` 不触发告警评估——面板刷出的快照主窗口「看得见、评不了」。

## Decision

**告警评估只发生在主窗口；告警文案一律「模板 + params」，落库存模板、渲染时按当前语言翻译。**

1. **评估权唯一化**：只有 `main` 窗口的 `observe` 真正执行，面板窗口的同名调用成为空操作（协调器仍保留，供广播的 `active` 表驱动展示）。补上评估缺口：主窗口在收到**别的窗口**的 `refresh-completed` 并重读快照后，用最新快照对全部实例重跑一轮评估——评估的输入是快照事实源的最新投影，「谁刷的」不影响「谁评估」。与「托盘写入方」「设置唯一写入口」同构：主窗口隐藏（驻留托盘）时 webview 存活、事件照收，评估不会停摆。
2. **告警态广播保持现状**：`alert-state-changed` 依旧只传 `active` 布尔表。面板是纯展示方，不需要边沿/冷却信息。
3. **文案模板化**：`AlertFire` 的 `title`/`body` 是中文模板（含 `{names}` 等占位符），与 `ProviderSnapshot.message/messageParams` 同构。系统通知在 fire 时刻按**当时**界面语言渲染（事件定性格）；`add_notification` 落库**模板 + params**，通知中心渲染时 `applyParams(t(title), params)`——切换语言后历史通知跟随，与程序其余文案行为一致。存量通知行没有 params，原样显示，自然兼容。
4. **协调器生命周期**：新增 `prune(instanceId)`，删除实例时清掉其全部规则键的边沿/冷却状态——常驻 webview 反复增删实例不再累积。
5. **顺带修正**：GLM 多源错误合并时 `{detail}` 占位符互相覆盖（`Object.assign(messageParams)`），改为每源先渲染再拼接；`en.ts` 清理死键、按新模板补齐键。

## Considered Options

- **Rust 端判重（评估下沉后端）**：可靠性最高、天然去重，但要把边沿/冷却状态迁移到 Rust 并让后端理解快照语义，改动面与收益不匹配；主窗口 webview 崩溃的场景下整个应用已不可用，不为它单独设防。
- **事件回填同步（广播带规则键+时间戳，各窗回填边沿表）**：用复杂协议模拟单点——双窗几乎同时越阈时谁都没收到对方的通知就先发了，时钟依赖与竞态仍在，不如直接单点。

## Consequences

- 告警评估频率 = 主窗口自身刷新 + 收敛重评估，面板刷新不再各评各的；重复通知消失。
- 主窗口职责进一步集中（托盘写入、设置写入、告警评估），「面板 = 快照事实源的纯投影」的模型更纯粹；后续若做 ADR-0019 预留的「托盘呈现下沉 Rust」，告警态的前端单点是其前置条件之一。
- 通知中心条目从「成品文案」变为「模板 + params」：新增语言无需迁移历史通知；但若未来改动模板措辞，历史通知的显示会跟着变（接受——通知是短期信息，一致性比定格重要）。
- CONTEXT.md 新增「告警评估方」「错误快照」词条；`applyParams` 保持纯模块（`src/i18n/apply-params.ts`），非 React 模块直接引入以避免循环导入（ADR-0021 已确立）。
