# 托盘用量环多层化：嵌套同心环

Status: accepted

## Context

ADR-0016 的「用量环」方案只画一个环 = 最紧窗口的已用百分比（`ring_percent` 单值），多层配额窗并存的实例（OpenCode Go 的 5h/周/月三窗、GLM 的 5h Token 窗 + 周配额 + MCP 月度用量）只能表达一扇，其余靠 tooltip 逐行兜底；「用量柱」方案上限两扇（三窗时月窗参与计分但不占柱位）。需求：用量环升级为可表达 1~3 层配额限制。

硬约束（事实核实）：

- Windows 100% DPI 下托盘图标就是 16px 物理像素（图标为自绘 RGBA 位图，系统不二次缩放），16/20/24/32px 四档 DPI；设计必须在 16px 成立。
- Rust 侧 tiny-skia 光栅化，无文字、零字体依赖；配色为静态品牌色、不随用量档位变化，任一活跃告警强制红（ADR-0016）。
- `update_tray_meter` IPC 固定 `ring_percent`/`bar_top`/`bar_bottom` 三个数值位，三层表达需扩展。
- 两套渲染实现需同步：Rust 托盘（16~32px）与前端 SVG（设置页 `TrayRingPreview` 34px、速览面板 `GlanceCards` UsageRing 44px）。

方案对比（两轮 16px 真实几何小样，候选：嵌套同心环 / 分段弧线 / 径向辐条 / 加粗内环嵌套环 / 分段饼盘 / 主环+内芯条 / 改良辐条）：细线系（嵌套环/分段弧）在 16px 三层时内环弧仅 ~1.6px 基本不可辨；实心系（饼盘/辐条）可辨性最强但与「环」视觉语言割裂、语义自解释弱。

用户决策：主方向选嵌套同心环的**内环加粗调优版**（语义与视觉一致性优先，接受 16px 三层低百分比内环只能辨「有无」的妥协）；层序按重置周期短→长；超三层取最紧三扇；badge 改绑外环百分比；升级现有 usage-ring 方案而非新增方案清单项。

## Decision

- **形态：嵌套同心环，内环加粗**。层数 = min(窗口数, 3)，单层形态与现状单环像素级一致（r=0.869s、stroke=0.15s、顶部起点顺时针、圆头端点，s=图标边长）。多层几何（16px 基准值，实现按 s 相对系数）：双层外环 r=6.67px/描边 2.0px、内环 r=3.67px/描边 2.2px；三层外环 r=6.67px/1.5px、中环 r=4.43px/1.8px、内环 r=2.2px/2.0px。内环加粗是刻意的可辨性补偿：半径越小弧长越短，加粗补回视觉重量。每层独立画「灰色轨道全环 + 品牌色进度弧」，起终点圆头，接近满圈留极小缝（沿用现状逻辑）。
- **层→窗口映射：按重置周期短→长**（外环 = 5h 短窗 → 内环 = 月长窗）。位置稳定，不随用量波动互换环位；半径形成「周期嵌套」隐喻。注意区分两个口径：层序键是**窗口周期时长**（5 小时/周/月），不是**下一重置时刻**（resetsAt）——后者是 ADR-0016 的 tooltip 行序与柱方案上→下口径，保持不变。周期时长由 provider 解析层结构化输出（快照行新增可选的窗口周期字段；OpenCode Go 的 rolling/weekly/monthly 与 GLM 的 TIME_LIMIT/TOKENS_LIMIT 在解析时已知），缺失时回退 resetsAt 近→远，再回退快照顺序；禁止用本地化 label 做文本匹配推断周期。
- **超三层截断：取最紧三扇入图**，三扇内部仍按周期短→长排环位；被挤出的窗继续 tooltip 逐行展示。与柱方案「参与计分但不占柱位」哲学同构。当前两家 provider 最多三扇，此条为防御性决策。
- **macOS badge：数字 = 外环（最短周期窗）百分比**，与图标最外那根环一一对应；单层时外环即唯一环，与现状行为一致。badge 数字来源从 `ring_percent`（最紧窗）改为层序首元素——消除「数字与图标视觉脱节」（旧语义下最紧窗可能在内环，数字 95 在外环找不到）。紧急性表达继续由告警红承担，badge 不承担。
- **tooltip 不变**：逐窗一行（resetsAt 近→远），天然覆盖三层。
- **告警视觉不变**：任一实例活跃告警 → 图标全部强制红。alert 为全局布尔，前端未知哪扇窗告警，层级告警粒度超出本次范围。
- **落地范围：升级 usage-ring**，方案清单保持 default / usage-ring / usage-bars 三项；旧单环形态即新环的单窗形态，不保留独立旧实现。
- **三处渲染面同步多层化**：Rust 托盘（16/20/24/32px）、设置页方案预览卡（34px，真实数据）、速览面板迷你环（44px，环心数字 = 最紧窗百分比保留，三层时数字字号与内环半径协调）。
- **实现注记（环心数字协调的落地口径）**：迷你环单层沿用自身 4px 细线基线（不被托盘 15% 相对描边同化），多层几何按 16px 基准 × size/16 缩放；环心数字单层 13px、双层 11px（内环孔径 ~14px）、**三层隐藏**（内环孔径仅 ~6.6px，放不下任何可读字号，窗口明细行有各窗读数兜底）。每层按自身用量档位着色（面板语言），托盘仍为静态品牌色。
- **几何常量单一来源**：多层 (半径, 描边) 常量在 Rust（`RING_LAYERS_TWO/THREE`）与前端（`lib/ring-layers.ts` `multiRingLayerSpecs`）各持一份同值副本，测试锁定（`ring_layer_specs_match_adr`）；单层几何不受多层化影响（托盘逐像素对比锁定）。
- **IPC 扩展**：`update_tray_meter` 新增可选 `ring_windows` 参数（层序百分比数组，≤3 元素，前端取最紧三扇并按周期排序后推送）；`ring_percent` 字段保留（单层回退与兼容），badge 优先取 `ring_windows` 首元素。

## Consequences

- 已知妥协留档：16px + 三层 + 内环低百分比时内环弧约 1.6px，只能辨「有无」不能读精确值；20px 及以上档清晰。tooltip 与速览面板兜底。若未来需反转此取舍，分段饼盘（实心扇区）是已对比过的替代形态。
- Rust：`draw_usage_ring` 重构为多层；`TrayMeter` 增 `ring_windows`；badge 来源调整；provider 解析层为快照行补结构化窗口周期字段。
- 前端：`use-tray-sync` 新增层序排序（周期短→长，独立于既有 `compareWindowReset` 的 resetsAt 近→远口径，后者继续服务 tooltip 与柱方案）；设置页预览卡同步多层化（速览迷你环见上方回修：维持单环）。
- 测试：Rust 像素级回归（四档尺寸 × 1/2/3 层：各层厚度、层间间隙、弧长-百分比映射、0% 无填充）；前端层序排序与截断用例。
- 方案清单、设置页交互、钉选与自动选例规则均不变（环方案展示的实例范围沿用 ADR-0016 口径）。
